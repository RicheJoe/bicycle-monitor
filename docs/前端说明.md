# 前端说明

客户端在 `web/`，用 uni-app（Vue 3）编写。当前要发布的是微信小程序。H5 用来在浏览器里看页面和调扫码、地图。业务规则以 `docs/技术方案.md` 为准。

## 本地运行

在 `web/` 下安装依赖后：

```bash
npm run dev:h5
npm run dev:mp-weixin
npm run build:mp-weixin
```

- H5 开发服务默认是 `https://localhost:5173/`。页面里要调相机，所以用本地证书，证书在 `web/.cert/`，由开发服务生成，不提交。
- `npm run dev:mp-weixin` 的产物在 `web/dist/dev/mp-weixin`。用微信开发者工具打开这个目录。
- `npm run build:mp-weixin` 的产物在 `web/dist/build/mp-weixin`，用于预览和上传。
- 上传前在 `web/src/manifest.json` 的 `mp-weixin.appid` 填入小程序 AppID。定位说明和 `getLocation` 已写在该文件里。

H5 地图需要高德 Key。复制 `web/.env.example` 为 `web/.env.development`，填入 `VITE_AMAP_KEY`。这个文件不提交。

## 页面

| 路径 | 作用 |
| --- | --- |
| `pages/map/index` | 附近地图。底部主按钮是「扫码用车」 |
| `pages/scan/index` | 确认开锁，也可手动输入车辆编号 |
| `pages/riding/index` | 骑行中的时长和预计费用 |
| `pages/return/index` | 核对定位和围栏后扫地面码还车 |
| `pages/profile/index` | 个人信息和入口 |
| `pages/orders/index` | 已完成订单 |

开锁流程：

1. 在地图页点「扫码用车」。
2. 微信小程序直接打开微信扫一扫。H5 进入开锁页，用页面内相机识别。
3. 解析出车身编号后弹出确认，确认后进入骑行页。
4. 「输入编号开锁」可以不扫码，用演示编号开锁。

还车流程：

1. 骑行中进入还车页，先看定位精度和是否在还车区。
2. 点「扫码还车」。小程序打开微信扫一扫，H5 用页面内相机。
3. 地面码有效、精度可用、人在该停车区半径加容差内，才结束订单。

## 平台差异

小程序没有 DOM。不要在小程序路径里使用 `document`、`window`、`navigator` 或往页面里插 `<video>`。

| 能力 | 微信小程序 | H5 |
| --- | --- | --- |
| 扫码 | `uni.scanCode`，只识别相机里的二维码。按钮文案是「扫码用车」或「扫码还车」，没有扫码框 | `CameraScanner`，用浏览器相机和 `@zxing/browser` |
| 地图 | 微信 `map`：车辆标记、停车区圆、当前位置 | 高德 JS API，容器是页面里的节点 |
| 定位 | `uni.getLocation`，`type` 为 `gcj02`，高精度 | 浏览器定位，再把 WGS-84 转成 GCJ-02 |
| 图标 | 用视图画出来 | Iconify |

条件编译写在页面里：`#ifdef H5` 放浏览器实现，`#ifndef H5` 放微信和 App 的原生实现。

相关文件：

| 文件 | 作用 |
| --- | --- |
| `src/components/RideScanButton.vue` | 「扫码用车 / 扫码还车」按钮 |
| `src/components/CodeScanner.vue` | 按平台选择按钮或相机 |
| `src/components/CameraScanner.vue` | 仅 H5 使用的相机扫码 |
| `src/utils/scan.ts` | 调用 `uni.scanCode` |
| `src/utils/locate.ts` | 按平台定位 |
| `src/utils/amap.ts` | 仅 H5 加载高德脚本 |
| `src/utils/qr.ts` | 解析 `/b/{code}`、`/p/{code}`，也接受纯编号 |
| `src/static/marker-bike.png` | 微信地图上的车辆图标 |
| `src/static/marker-park.png` | 微信地图上的停车点图标 |

## 演示数据

车辆和停车点写在 `src/data/places.ts`，坐标相对第一次可用定位偏移，避免点跟着人漂移。

| 类型 | 编号 | 说明 |
| --- | --- | --- |
| 车辆 | `BK8K2M`、`BK2P9L`、`BK7Q1C` | 可手动开锁 |
| 停车点 | `PK3N7Q` | 脚下还车点，启用 |
| 停车点 | `PK9W4D` | 东北还车点，启用 |
| 停车点 | `PK0X1Z` | 南侧还车点，停用，扫码应拒绝 |

还车页可以用「当前定位 / 区域内 / 区域外 / 定位不准」切换演示结果。正式环境只保留当前定位。

`docs/qr/` 里有两张演示图：`unlock-BK8K2M.png` 是车身码，`return-PK3N7Q.png` 是地面码。小程序扫码只允许相机，可以把这两张图展示在另一块屏幕上再扫。

围栏容差 15 米，精度上限 30 米，定义在 `src/data/mock.ts`。

## 目录

```text
web/
  src/pages/          页面
  src/components/     扫码按钮、相机、图标
  src/utils/          定位、扫码、坐标、计费
  src/data/           演示车辆、停车点和规则常量
  src/store/          当前订单、历史订单、定位
  src/static/         小程序地图标记
  src/manifest.json   小程序权限与 App 配置
  src/pages.json      路由
```

订单和骑行状态存在本地存储里，刷新后还在。接入 `api` 之后，开锁、还车和附近查询改为请求服务端，页面上的判定只作演示。
